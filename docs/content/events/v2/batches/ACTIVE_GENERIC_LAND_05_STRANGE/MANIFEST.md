## Existing controlled definitions used

### Persistent NPC

- `childhood_friend` — reused by exactly one restricted festival scene; declared in `cast`; relationship changes are +3 / +5 only when the friend directly participates.

### Crew roles

Optional conditioned approaches use only existing roles:

- `cook`
- `shipwright`
- `helmsman`

These options are never the only resolvable Choice.

### Item

- `timber` — one conditioned sacrifice in `rolling_house`; the Choice requires `hasItem(timber)` before `removeItem`.

### Location metadata

- service: `food`
- tags: `urban`, `historic`

### Stats / Dice

Dice uses only existing attributes:

- `agility`
- `strength`
- `observation`
- `intelligence`
- `charisma`

Stats are secondary consequences rather than automatic rewards; normal failures still cost Health/Berrys/opportunity even when Stat delta is zero.

### Effects

Only existing Effects are used:

- `queueImmediateEvent`
- `modifyHealth`
- `modifyBerries`
- `modifyReputation`
- `modifyStat`
- `modifyNpcRelationship`
- `removeItem`

There is no `scheduleEvent`, `moveToLocation`, career/rank/title mutation, bounty mutation, flag creation, Trait grant, NPC status mutation, ship mutation or new persistent state.

## Consequence spread

The batch deliberately mixes:

- Health loss from physical comedy and machine/animal accidents;
- Berry loss from damaged stalls/equipment and small participation costs;
- small positive Berry prizes on a few competitions;
- monotonic positive Reputation for publicly visible saves/performances;
- `childhood_friend` relationship changes in one recurring-cast scene;
- one existing-Item sacrifice (`timber`);
- one-shot History/opportunity outcomes with no compensating reward;
- occasional ±1 Stat consequences, mostly on critical Dice results rather than every successful action.
